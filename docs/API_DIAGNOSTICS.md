# DeepSeek 接口故障诊断与兼容原理

日期：2026-11-24。版本：0.2.1。

## 已知现象与结论边界

用户已填 DeepSeek 官方地址并表示密钥正确；随后截图显示角色开场白、第一条用户发言，以及“模型接口返回 HTTP 400”。旧版未保留服务端 error.message，所以目前无法从截图确定唯一根因。没有用户密钥，也没有抓取手机真实请求，不能把模拟测试称为官方 API 联调。

截图证明应用已在用户手机显示聊天界面并到达 HTTP 错误处理路径；它不证明模型名称、账户额度或具体请求格式都正确。官方将 400 对应到请求格式、401 对应认证、402 对应余额、422 对应参数、429 对应限流：[DeepSeek 官方错误码](https://api-docs.deepseek.com/zh-cn/quick_start/error_codes/)。

## 0.2.1 的调整

### 开场白与 API 消息顺序

旧版第一轮为 system → assistant 开场白 → user。本版保留屏幕中的开场白与原始数据，但将尚无用户轮次的开场白作为 system 内的已说过内容，实际聊天数组从 user 开始。长历史截断仍以用户轮次为边界。

这是兼容性加固，不是已经由官方错误详情证实的本次 400 根因。若仍失败，应读取新版服务端说明再决定修改，不能继续猜测或删除用户记录。

### 普通聊天参数

DeepSeek 当前官方文档列出 api.deepseek.com 与 deepseek-flash/deepseek-v4-pro。官方模型默认启用思考；本应用目前定位普通角色聊天，尚未提供思考模式或工具调用，所以对精确官方主机显式发送 thinking.type=disabled。其他兼容服务不接收此特定字段。

资料：[首次调用](https://api-docs.deepseek.com/zh-cn/)、[思考模式](https://api-docs.deepseek.com/zh-cn/guides/thinking_mode/)。该参数调整不能保证解决所有 HTTP 400。

### 连接测试与模型选择

设置页“测试连接 / 获取模型”请求当前基础地址下的 GET /models，使用表单 Key；留空时使用保存的 Key。它不提交人物、聊天正文或生成请求，结果只保存在内存，不自动保存设置。官方接口见 [获取模型列表](https://api-docs.deepseek.com/zh-cn/api/list-models/)。

成功后可从返回列表选择模型，再保存配置。读取列表成功不能证明账户有生成额度；某些通用服务可能没有 /models，失败也不能直接推断其聊天不可用。此测试没有进行自动反复生成重试。

### 可复制的错误详情

旧版短提示改为保留到手动关闭的弹窗，显示状态、主机、模型、服务端 code/type/message、可用请求编号。仅提取结构化字段，错误体上限 16 KiB，说明字段上限 800 字符；不把整段 HTML、请求头和聊天正文直接输出。

已知 Key、Bearer token 与常见 sk- 字符串先脱敏再显示或复制。诊断信息不落盘。网络断开、域名解析、HTTPS 连接和超时与 HTTP 服务端错误分开处理。

## 用户的验证路径

1. 用同签名 0.2.1 APK 覆盖安装，保留已有人物与聊天；不用卸载。
2. 打开接口设置，点击“填入 DeepSeek 官方配置”。已有 Key 留空保留，或在手机重新填写；不向开发者发送密钥。
3. 测试连接。若返回模型列表，从列表选择并保存；若失败，复制错误详情定位认证、地址或网络问题。
4. 回到原聊天点击“重试回复”。本次未完成的用户消息不会重复插入。
5. 若仍出现 400，复制服务端说明和模型 ID；根据具体文本决定后续修复。当前不把“已发布诊断版”写成“用户真实调用已修复”。

## 已执行验证

Android 编译成功，36 项单元测试通过。新增测试采用 OkHttp 应用拦截器返回固定响应，不访问真实接口、不用真实 Key。覆盖请求地址/头/普通模式、开场白请求转换、400 详情与脱敏、402、JSON 错误、模型列表 GET、文本块、非法 Key，以及不自动重试。

用截图可见字段构造了近似对话夹具，仅用于检查本机序列化；它不是真实手机抓包或真实 DeepSeek 复现。APK 与 0.2.0 证书相同，签名和 ZIP 对齐检查通过。新版用户侧模型发现与聊天生成结果仍待确认。
