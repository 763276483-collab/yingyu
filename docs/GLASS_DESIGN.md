# 玻璃聊天界面的方案与程序原理

版本：0.2.0，日期：2026-11-24。用户要求聊天框使用高斯模糊或类似液态玻璃的材质，让壁纸可见。当前源码实现静态壁纸的局部高斯模糊、半透明透色与高光轮廓。Android 编译与高斯基础单元测试已通过，真机视觉验收仍待进行。

## 显示规则

- 整张聊天壁纸保持清晰，只在气泡、聊天标题栏和输入栏内显示模糊后的同位置背景。
- 默认透色层浓度为 18%，加一层很淡的渐变反光和 1 dp 高光边；外观菜单可调整浓度与模糊强度。
- 文字和按钮在玻璃背景之后绘制，保持清晰。默认白字加轻微阴影，浅色壁纸可切换深色文字。
- 用户气泡略带浅蓝，角色气泡用淡白色；依然允许透过玻璃看到壁纸结构。
- 壁纸是全局静态图片，外观设置影响所有聊天。每个人物独立壁纸、动态视频壁纸和随手势变化的光学折射留待后续需求。

这是玻璃视觉风格，并没有移植苹果系统材质或实现其动态折射模型。任意壁纸上的可读性需要实测，用户可在保留通透感的同时提高透色层或改深浅文字。

## 为什么不直接模糊聊天框

Compose 的 Modifier.blur 模糊被修饰组件自身绘制的内容，包括其文字与子组件；它不等于读取后方壁纸。Android 官方对两类模糊有明确区分：[Compose 模糊说明](https://developer.android.com/develop/ui/compose/graphics/blur/overview)。

本工程不在包含文字的容器上调用该效果，而是仅对单独的壁纸像素计算高斯模糊，再作为玻璃组件的背景。

## 缓存与高斯卷积

1. WallpaperStore 把照片缩到最长边 1600 像素以内，纠正方向，合成透明像素并保存 JPEG。背景加载在 IO 线程。
2. rememberGlassBackdrop 在 Default 线程把图像降采样到最长边 384 像素以内。按屏幕密度与壁纸的放大比例，把界面的模糊参数换算成缓存图中的 sigma。
3. GaussianBlur 使用归一化高斯权重，先水平方向、再垂直方向卷积；边界采用最近像素延伸，避免透明黑边。输入是已经合成的不透明壁纸，因此仅滤 RGB 并保持 alpha=255。
4. 共享一份模糊结果。只有更换壁纸、模糊强度、屏幕尺寸或密度时重新计算；聊天滚动、文字输入与透明度调整不会重新计算卷积。
5. 卷积按行检查协程取消，快速连续调整时取消过时任务。缓存生成前暂时显示清晰背景与透色层，不使用不透明占位块。

sigma 是高斯分布标准差；界面“模糊强度”不是像素级物理半径。算法在小缓存上运算，再放大显示，兼顾旧手机的适应性；真实滚动帧率和耗电仍需设备测试。

## 如何保证图案对齐

壁纸采用居中裁剪，scale = max(视口宽/图宽, 视口高/图高)。全局壁纸与所有玻璃组件都使用同一个目标矩形。

每个 GlassSurface 用 positionInRoot 获取自己的位置，减去壁纸原点位置，再以这个偏移绘制共享模糊图，最后裁剪圆角。这样气泡看到的是自己后面的壁纸位置，而不是把整张图片压缩进每个气泡。

当前仅采样壁纸，不捕获其他消息或任意实时界面内容；输入栏与列表在布局中各占空间，避免消息滚入输入栏后出现“该模糊什么”的歧义。没有逐帧截图或昂贵的 UI 抓取。

## 兼容性与本地图片

基于位图卷积和 Compose Canvas，从最低 Android 8.0 开始采用相同渲染策略，不依赖系统窗口模糊开关。Android 9 起使用 ImageDecoder，设置软件位图与目标尺寸；Android 8.x 使用 BitmapFactory 降采样和 EXIF 变换。参考 [Android ImageDecoder](https://developer.android.com/reference/android/graphics/ImageDecoder)。

通过系统 OpenDocument 选择图片，不请求整个相册的存储权限。选中后立即复制到应用私有目录，不长期依赖源 URI；图片不参与聊天或语音网络请求。导入上限为 20 MiB，源图片丢失不会影响已复制的壁纸。系统文档选择流程见 [Android 共享文档访问](https://developer.android.com/training/data-storage/shared/documents-files)。

实际运行前需要检查大图、透明 PNG、横向照片、EXIF 旋转与镜像、无效图片和读取失败。动态图片只取静态解码帧，不播放动画。

## 持久化与调试

appearance 加到 AppData，格式从 v1 升到 v2。迁移前保留原始 JSON 字节；图片独立保存。导入新图片后先原子提交配置，再删除旧壁纸；若配置提交失败，删除新图并继续保留旧配置。

壁纸布局错位时先检查两个 drawWallpaper 的居中裁剪矩形是否一致，再检查 positionInRoot 与原点，最后检查键盘或旋转后的 viewport。模糊文字则先排查是否把模糊误加到内容层。卡顿时统计卷积触发次数与主线程耗时，确认没有在每个列表项或每帧重新滤图。

至少在 Android 8.x、一个主流新版本设备上实测，使用高对比图案观察滚动时的背景连续性；再用深色、浅色、照片三类壁纸验证中文长消息、文字选中、输入焦点、键盘、历史切换和横竖屏。
