## D001 原生 Kotlin 与 Compose

日期：2026-11-24。状态：初版采用，可调整。

当前目标只有 Android，原生方案便于接系统 TTS、Android Keystore 和后续本地推理库。暂不引入跨平台框架；若用户明确需要 iOS 或桌面，再评估共享数据层与 UI 成本。

构建基线固定 AGP 8.9.2、Gradle 8.11.1、Kotlin 2.1.20、JDK 17、SDK 35。它们是可复现的工程基线，不表示最新版本，也不表示已满足未来应用商店提交要求。版本兼容说明参考 [AGP 8.9 官方记录](https://developer.android.com/build/releases/agp-8-9-0-release-notes) 与 [Compose Kotlin 编译器说明](https://developer.android.com/jetpack/androidx/releases/compose-kotlin)。

## D002 首先支持兼容聊天协议

原因：用户尚未指定聊天供应商，采用可配置基础地址、模型 ID 和密钥的 Chat Completions 文本接口。模型切换无需编辑人物卡。其他供应商的原生协议不能假定兼容，后续增加独立适配器，不用修改 URL 假装支持。

## D003 人物和语音解耦

原因：人物名字与设定控制文字，语音模型与音色控制声音。一个人物可更换语音方案而不更换聊天接口。未来可扩充情感、风格、声音设计，但不能把文字设定中的声音描述当成已完成音色生成。

## D004 云端语音优先

最初实现系统 TTS 路径以验证基础结构。收到用户“优先自然、有角色感的云端语音”后，将新人物默认值改为 CLOUD，并加入 MiniMax 完整音频合成与播放。系统 TTS 保留供用户选择；不在云端出错时自动切换，避免声音突然变化和隐含网络行为。

先实现手动朗读和非流式音频，方便验证音色与错误处理。下一阶段优化为分句调度和流式播放之前，先确认真实音色、计费和延迟。CosyVoice 作为第二候选，不提前同时接多家不同协议。

## D005 本地快照存储

初版使用带格式版本的 JSON + AtomicFile，减少数据库生成工具依赖，让原型便于审阅。缺点是每次写入全部数据，长聊天性能不足。进入长期使用、搜索、删除和备份阶段前迁移到 Room；不能把此方案无限扩展。

## D006 冻结每段对话的角色

原因：保证调整人物卡不会意外改变旧对话。新对话使用最新人物卡快照。全局聊天与语音模型仍可切换；若要求精确重现旧结果，需要额外记录请求参数和提示词版本。

## D007 用户自己的 Key 分别保存

聊天 Key 与语音 Key 独立加密，方便选择不同服务，不互相试用密钥。采用 Android Keystore 保存加密材料，不在源码中放开发者公共 Key。若改成开发者统一付费，必须增加后端代理。

## D008 一条生成任务与显式重试

先限制同时生成一条聊天回复，避免多条消息乱序和并发覆盖保存。网络失败保留已保存用户消息，重试不再重复插入。关闭网络层自动连接重试，不自动重复收费请求。后续多会话并发时需改成每个会话独立任务与数据库事务。

## D009 保存文档与代码一起迭代

由用户明确要求。每次改动更新需求、架构、决策、验证和日志；重要未验证事实必须标注，后续开发读取 AGENTS.md 继续执行。源码工程就是这一轮的持久交付，不依赖聊天上下文作为唯一记录。

## D010 壁纸高斯模糊与玻璃高光

日期：2026-11-24，版本：0.2.0。用户追加要求：聊天框使用高斯模糊或类似苹果液态玻璃的通透材质，让聊天壁纸可见。

采用清晰壁纸底层 + 共享低分辨率高斯缓存 + 各组件局部取样 + 淡色高光边。消息、标题与输入栏使用同一玻璃组件，文字在最后绘制。可调通透程度、模糊强度与文字深浅，全局壁纸通过系统选择器导入。

没有选择直接对包含文字的组件调用 blur，因为那会处理其自身内容；也未引入只能在较新 Android 上使用的系统背景模糊或复杂折射着色器。当前方案覆盖最低版本，滚动时不重算卷积。代价是只处理静态壁纸，不具备苹果系统材质的动态折射、动态背景采样和自动对比度适应；真机测试后再决定进一步的 GPU 优化。

## D015 0.2.2 真机视觉修复与 MiniMax 业务诊断

日期：2026-11-24，版本：0.2.2（versionCode=4，保持原调试签名与数据格式 v2）。

真机（华为 Mate 20 Pro / Android 10）实测 0.2.1 时，确认 DeepSeek `GET /models` 与单轮对话已通，但直接暴露出四项界面与诊断问题：
1. 聊天页上下留有白色系统栏，削弱玻璃壁纸沉浸感 → 改为 `ChatScreen` 路由铺满全屏壁纸，内部按 `statusBarsPadding()` / `navigationBarsPadding()` / `imePadding()` 避让，并用 `WindowCompat` 随 `darkText` 切换系统栏图标色。

## D021 0.3.3 模拟打字机节奏（方案 A）、全应用转场与沉浸式微动效

日期：2026-11-24，版本：0.3.3（versionCode=10，保持 `com.rolechat.app` 包名、原调试签名与数据格式 v2，无数据模型变更）。

- **模拟逐字打字（方案 A）而非改动 SSE 流式协议**：与用户讨论后选用方案 A，避免各家 OpenAI 兼容服务商 SSE 差异带来的稳定性风险；通过 `MainViewModel.animatingMessageId` 仅对新落盘的 AI 回复触发逐字显示，与 `voice.speak` 同步开始，点击气泡可随时跳过并展开全文，退出或回溯时自动清理动画状态。
- **自然节奏控制**：`TypewriterPacing` 对句末/句中标点施加短停顿，长文本（>80 / >200 / >320 字）自动提速并调整步长，括号旁白以 0.6x 速度快速掠过，且 `formatRoleplayText` 在未闭合括号期间即维持柔化透明度。
- **主界面与聊天细节抛光**：首页加入 `StaggeredEntrance` 交错入场、整卡点击轻弹、流动渐变 CTA 与空态品牌插画；全路由通过 `AnimatedContent` 统一滑动淡入；聊天页新增壁纸淡入微缩放、角色侧三点弹跳玻璃等待气泡、朗读中顶部头像脉冲光环、💡 建议交错弹出以及关键操作触感反馈。

## D022 0.3.4 沉浸聚焦模式（一问一答）与陀螺仪壁纸视差

日期：2026-11-24，版本：0.3.4（versionCode=11，保持 `com.rolechat.app` 包名、原调试签名与数据格式 v2 向后兼容）。

- **沉浸聚焦模式**：按用户确认采用「最近一问一答 + 原地展开/收起 + 气泡上方小胶囊」方案。`Conversation.latestTurnWindow()` 在存在更早记录时仅保留最新用户发言与最新角色回复并底部对齐；点击 `⌃ 查看前文（N）` 原地展开完整消息与「简介」浮卡，按钮停留在历史与最新对话交界处并变为 `⌄ 收起前文`，既不挡脸又方便长按历史消息做回溯或删除。
